# 国特优化执行方案

## 目标

将项目从“功能覆盖完整”升级为“可量化、可复现、可治理、可在国产化环境落地”的工业检修智能系统。所有答辩结论必须能追溯到代码、测试、实验结果或实机记录。

## 三条答辩主线

1. 可信诊断 Agent：手册、案例、知识图谱和设备历史交叉验证，结论逐条关联证据。
2. 知识闭环治理：一线纠正、审核发布、版本回滚和操作审计形成可控演进闭环。
3. 国产化工程落地：LoongArch + 银河麒麟可安装、可运行、可恢复，并提供离线预案。

## 量化目标

| 指标 | 目标 |
|---|---|
| 核心需求覆盖率 | 100% |
| 检索 Recall@5 | >= 0.90 |
| 引用准确率 | >= 0.95 |
| 无依据回答率 | <= 0.05 |
| Agent 结构化动作解析成功率 | >= 0.99 |
| Agent 任务完成率 | >= 0.95 |
| 1 万分块检索 P95（不含外部模型） | < 300 ms |
| 30 并发请求错误率 | < 1% |
| LoongArch 稳定运行 | 8 小时无崩溃 |

## 执行规则

- 不再新增与主线无关的展示型功能。
- 未经实测的能力只能标为“设计目标”或“待验证”，不得写成既成事实。
- 每个阶段同时提交实现、测试、指标结果和文档，不接受只有截图或 PPT 的完成状态。
- SQLite 是演示回退；生产检索结论以 PostgreSQL + pgvector 实测为准。
- 固定衰减和启发式评分在完成校准前统一称为“可解释评分”，不称为统计置信度。

## 当前硬边界

- 当前开发机没有 `TEST_POSTGRES_URL`，真实 pgvector 集成用例会跳过；合并前必须保留 CI 成功记录。
- 当前开发机不是 LoongArch/银河麒麟，不能产出国产化实机结论；必须在目标机运行 `deploy/05_collect_loongarch_evidence.sh`。
- 大模型 Agent 指标依赖真实模型和生产知识库，必须运行 `evaluation/evaluate_agent.py` 后才能写入答辩数值。
